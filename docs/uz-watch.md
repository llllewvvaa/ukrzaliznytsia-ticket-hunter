# УЗ-сторож: моніторинг квитків без акаунта

Серверна частина цього репозиторію (`server/`) і Telegram Mini App (`miniapp/`) — це окремий від розширення інструмент: він **лише стежить і сповіщає**, нічого не бронює й не купує.

## Чому це працює без логіну

Виміряно 2026-09-08/09:

| Перевірка | Результат |
|---|---|
| `GET /api/v3/trips` зі справжнього браузера, без `Authorization` | 200, 33–35 КБ, 30–31 рейс |
| той самий запит curl'ом із тими самими заголовками | 441 + `recaptcha_link` |
| `GET /api/v3/trips/{id}` як гість | 200, `route_points` — повний список зупинок |
| `GET /api/v3/trips/{id}/wagons-by-class/К` як гість | 200, `seats: [15,16,21,…]`, `free_seats_lower`, `free_seats_top` |
| `booking.uz.gov.ua` через curl | 403 Cloudflare |

Гейт відсіює не гостя, а не-браузер. Тому запити йдуть **з контексту сторінки booking.uz** у резидентному Chromium (`src/net/browser.ts`), а акаунт не потрібен ніде: банити нічого, лишається тільки IP-рівнева ввічливість.

Заголовки гостя (`src/uz/headers.ts`): `x-user-agent: UZ/2 Web/1 User/guest`, випадковий `x-session-id`, `x-client-locale: uk`.

## Архітектура

```
Chromium (Playwright, профіль на диску) ──page.evaluate(fetch)──▶ app.uz.gov.ua/api
        │
   uz-client         guest-заголовки, ретраї, 429/441-політика, хеш тіла
   cache + log       SQLite: response_cache, request_log
   atlas             route_points → trip_route → pair_index (локально, без мережі)
   brain             candidates (4 рівні) + rank (найдешевше / баланс)
   watch engine      probe (адаптивна частота) + diff + seat step + route_memory
   api + bot         node:http + grammY
   miniapp           React: Пошук / Улюблені / Історія
```

## Економія перебору

1. **Безкоштовний перебір потягів.** Один запит `(пара, дата)` повертає всі рейси дня, включно з тими, де місць нуль. Ціна перебору міряється в парах-датах, не в потягах.
2. **Холодний шар окремо.** Маршрути й зупинки тягнуться раз (`pnpm atlas:build`) і живуть у `trip_route`/`pair_index`. Побудова кандидатів — чистий SQL, нуль мережі (перевірено тестом `costs nothing in network calls`).
3. **Адаптивна частота.** Кожна `(пара, дата, режим)` має рядок `probe`: однаковий хеш відповіді → інтервал ×1.6 до 30 хв (уночі ×4); зміна → падіння до 2 хв.
4. **Пріоритет замість кола.** `scoreProbe` = вага кандидата + частота змін + прострочення + близькість відправлення + улюблене. Планувальник бере top-N у межах token-bucket (`UZ_PER_HOUR`, стартово 300/год).

Плюс: дедуплікація однакових пар між стеженнями, дисковий кеш відповідей, `wagons-by-class` лише для шортліста і не частіше разу на 2 хв на рейс.

## Що вміє мозок

- прямі рейси;
- пересадки самої УЗ (`with_transfers=1`);
- **наскрізні сегменти**: якщо квитка A→B немає, шукає A→C (їхати далі) і C′→B (сісти раніше) по `route_points` того ж потяга;
- сусідні станції обох кінців і сусідні дати (`--slack`);
- ранжування: `cheapest` (типово) або `balanced` (ціна+час+пересадки+тип обходу).

Живий приклад: Київ→Львів, прямий плацкарт 276 грн, а через «їхати далі до Івано-Франківськ потягом 001О» знаходився варіант там, де прямих місць уже не було.

## Стеження до місць

Крок 1 (дешевий): `free_seats` і `price` з пошуку → події `appeared`, `price_drop`, `more_seats`, `gone`.
Крок 2 (дорогий, лише для шортліста): `wagons-by-class` → номери місць, нижні/верхні, ціна вагона, послуги. Правила: `berth: lower|upper`, `minSeats`, `adjacent` (пара сусідніх), `airConditioned`.

## Команди

```bash
cd server
pnpm install
pnpm test                 # 134 тести, без мережі
pnpm compile              # strict tsc
pnpm probe                # живий пошук, друкує статус і найдешевші класи
pnpm probe:seats -- --trip <id> --class К
pnpm atlas:build -- --from 2200001 --to 2218000 --days 3
pnpm ways -- --from 2200001 --to 2218000 --date +7 --slack 1
pnpm watch:demo -- --minutes 20 --cycle 60
pnpm stats:budget -- --hours 24
pnpm forecast             # список потягів, за якими вже є історія
pnpm forecast -- --train 017О --class К --horizon last_day
pnpm serve                # демон: цикли + HTTP + бот
pnpm dev:serve            # те саме без Telegram-авторизації (локальна розробка)
pnpm dev:force-event      # звести подію на реальних даних, щоб перевірити ланцюг
```

Mini App:

```bash
cd miniapp
pnpm install
pnpm dev       # http://localhost:5188, проксі на :8848
pnpm build     # dist/, який роздає сервер
```

## Телеграм

1. У BotFather створити бота, узяти токен.
2. `UZ_BOT_TOKEN=<токен>`, `UZ_CHAT_ID=<твій chat id>`, за бажанням `UZ_ALLOWED_CHATS=<id через кому>`.
3. У BotFather `/newapp` або `/setmenubutton` — вказати публічний HTTPS Mini App і покласти його ж у `UZ_MINIAPP_URL`.
4. `pnpm serve`. Команди бота: `/start`, `/ways Київ Львів +7`, `/watch Київ Львів +7 3`, `/list`, `/fav 1`, `/pause 1`, `/resume 1`, `/cheapest`, `/stats`.

Без токена сервер працює як є: стежить, пише події в базу, показує їх у Mini App і CLI.

## Прогноз

`forecast()` рахує з власної історії `snapshot`: скільки разів після порожньої перевірки місця зʼявлялися, окремо по горизонтах (`last_day`, `three_days`, `week`, `far`), плюс медіанну ціну. Поки порожніх спостережень менше за поріг (типово 20), функція повертає `null` і пише «недостатньо даних» — вигаданих чисел не показує. Ендпоінт: `GET /api/forecast?train=017О&class=К`.

## Налаштування

`server/.env.example` — повний перелік. Головне: `UZ_PER_HOUR` (стеля запитів), `UZ_MAX_PROBES` (за цикл), `UZ_CYCLE_MS`, `UZ_BOT_TOKEN`, `UZ_CHAT_ID`, `UZ_ALLOWED_CHATS`, `UZ_MINIAPP_URL`, `UZ_DEV_NO_AUTH=1` для локальної розробки без Telegram.

## Розгортання

`deploy/uz-watch.service` (systemd + Xvfb для Dell), `deploy/com.uzwatch.server.plist` (launchd для Mac), `deploy/backup.sh` (бекап SQLite). Mini App потребує публічного HTTPS — тунель піднімається окремо.

## Межі

Ніякої броні, оплати, обходу reCAPTCHA й опитувань частіше за фейр-плей floor'и. Прогноз появи квитків зʼявиться лише після накопичення історії в `snapshot`.

## Простішими словами

Це сторож, який дивиться за квитками замість тебе.

На машині відкритий один браузер на сайті УЗ. Через нього програма питає те саме, що питає людина: «чи є місця з A в B на таке число». Виявилось, що для цього не треба входити в акаунт — сайт відповідає й гостю. Отже, немає чого банити; є лише правило «не питай надто часто», і ми його дотримуємось: рахуємо кожен запит, робимо паузи, вночі перевіряємо рідше.

Коли прямих квитків немає, сторож не здається. Він уже знає маршрути потягів — де кожен зупиняється — і пробує обхідні варіанти: вийти на станцію далі, сісти на станцію раніше, поїхати сусіднього дня, скласти дорогу з двох потягів. Усе це вигадується локально, з бази, і не коштує жодного звернення до УЗ.

Далі він дивиться конкретні місця: скільки нижніх, скільки верхніх, які номери, скільки коштує вагон. І пише в Telegram, коли щось зʼявилось або подешевшало. Керувати можна з Mini App: вкладка «Пошук» шукає дорогу зараз, «Улюблені» тримає постійні напрямки під наглядом, «Історія» показує події й статистику економії.

Купувати він нічого не буде — тільки знаходити й повідомляти.
